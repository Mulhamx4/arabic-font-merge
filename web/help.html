الخط لا يظهر؟

الأعراض التي يبلّغ عنها الناس نادرًا ما تكون السبب الحقيقي. اتبع الترتيب: الخطوات الأولى رخيصة وتلتقط أغلب الحالات.

٠ — هل المشكلة في الملف أصلًا؟

افتح صفحة الاختبار الذاتي التي نزّلتها من الخطوة الخامسة، في أي متصفح. الخط مضمَّن داخل الصفحة، فالتثبيت لا دخل له.

  • الرموز تظهر ← الملف سليم. كل ما تبقى مشكلة تثبيت أو كاش أو تطبيق. توقّف عن فحص الخط.
  • الرموز لا تظهر ← المشكلة في الملف نفسه. ارجع وأعد البناء، وراجع تقرير التحقق.

هذه الخطوة وحدها توفّر جولة تخمين كاملة، ولهذا صفحة الاختبار متاحة من اليوم الأول.

الرمز غير موجود في «خريطة المحارف»

متوقَّع، وليس عطلًا. رموز العملات الثلاثة حديثة في يونيكود، و«عارض المحارف» في ماك و«Character Map» في ويندوز يقرآن قاعدة بيانات يونيكود في نظام التشغيل لا الخط. فما لا يعرفه النظام لن يُدرج ولو كان داخل الخط.

  • أدوبي: Type ▸ Glyphs مع Show: Entire Font، ثم انزل لآخر القائمة. المحارف المضافة حديثًا تأتي في النهاية. هذه اللوحة تقرأ الخط مباشرة.
  • أي مكان آخر: الصق الحرف، أو اكتب الاختصار (SAR أو ر.س…).

ثبّتُّ الخط ولم يتغيّر شيء

هذا كاش في الغالب الأعم. الترتيب من الأنجع إلى الأقل:

  1. ارفع رقم الإصدار وأعد البناء. الكاش مفهرس باسم PostScript، فرفع الإصدار يجعله يرى خطًا مختلفًا. هذا هو الحل الذي يعمل فعلًا؛ ما بعده نظافة.
  2. احذف النسخة القديمة أولًا. نفس الأسماء الداخلية تعني أن النظام قد يعود إلى الملفات الأصلية. في ماك: «كتاب الخطوط» ← اختر العائلة ← إزالة. أو أعد البناء مع لاحقة اسم جديدة، فينتفي التعارض من أصله.
  3. كاش أدوبي: أغلق كل تطبيقات أدوبي، ابحث عن AdobeFnt*.lst واحذفها (مواضعها متعددة)، ثم أعد التشغيل.
  4. أعد تشغيل التطبيق. التطبيقات تُعدّد الخطوط عند فتحها. هذه وحدها تحل نسبة مفاجئة من البلاغات.
  5. كاش ماك كحل أخير: sudo atsutil databases -remove ثم سجّل خروجًا ودخولًا.

ملف otc لا يُثبَّت على ويندوز

ليس عطلًا في الملف. مستكشف ويندوز لم يسجّل امتداد .otc كنوع خط إطلاقًا، فلا يعرض خيار «تثبيت» له. الحل هو صيغة ttc من قائمة صيغة الإخراج — تحوّل المسارات من CFF إلى TrueType، وويندوز يدعم ttc منذ عقود (خطوط النظام نفسها كذلك).

فراغ زائد حول الرمز

افحص العرض المُشفَّر قبل أن تلمس الهوامش. محرف CFF يخزّن عرضه مرتين: في hmtx، وداخل الـ charstring كإزاحة عن nominalWidthX. لو كُتب العرض المطلق في الثاني اكتسب المحرف فراغًا ميتًا — تراه تطبيقات أدوبي ولا تراه المتصفحات، لأنها تقرأ hmtx. تقرير التحقق يقارن الاثنين لكل محرف؛ لو ظهر «تعارض عرض» فهذا هو.

الاختصار لا يتحوّل

  1. الاختصارات مبنية على خاصية calt، وهي قابلة للإطفاء في Illustrator وInDesign (Contextual Alternates في لوحة المحارف). تأكد أنها مفعّلة.
  2. القواعد محمية عمدًا: الاختصار لا يعمل إذا جاوره حرف. SAR 10 تعمل، وSARAH لا تعمل — وهذا مقصود، وإلا لأصبحت كل كلمة فيها SAR مكسورة.
  3. AED500 بلا مسافة ستعمل، لأن الرقم ليس حرفًا. سلوك مقصود.

العائلة متناثرة في قائمة الخطوط

خطأ شائع في الخطوط المنشورة: سجل nameID 2 في منصة ويندوز يقول Regular لكل الأوجه بما فيها Bold Italic. البناء يصلح هذا بإعادة كتابة السجلات 1/2/16/17 من مصدر واحد. لو بقيت متناثرة بعد البناء، فالتطبيق يقرأ من كاش قديم — راجع القسم أعلاه.

العربي يظهر بخط مختلف داخل المائل

عائلات كثيرة تشحن العربي في المستقيم فقط، فيسقط العربي في المائل إلى خط النظام. فعّل «نقل العربي إلى المائل» في خيارات التعديل. العربي يبقى مستقيمًا داخل اللاتيني المائل، وهذا هو المتعارف عليه لا تنازل.

شكل الرمز يبدو غريبًا في خطي

الرسم الرسمي للرموز هندسي. في خط نسخي أو شديد التزيين سيبدو دخيلًا بعض الشيء، ولا حل تقنيًا لذلك: الرمز علامة رسمية لها رسم واحد معتمد، ورسم نسخة «متناسقة» منه عمل مصمّم حروف لا سكربت.

Font not showing up?

Reported symptoms are rarely the actual cause. Work the list in order — the early steps are cheap and catch most cases.

0 — Is it the file at all?

Open the self-test page you downloaded in step five, in any browser. The font is embedded in the page, so installation is irrelevant.

  • Symbols show → the file is fine. Everything else is installation, cache, or the application. Stop inspecting the font.
  • Symbols missing → the file itself is wrong. Rebuild and read the verification report.

This step alone saves an entire round of guessing, which is why the self-test exists from day one.

The symbol is not in the character map

Expected, not a bug. These three codepoints are new in Unicode, and macOS Character Viewer and Windows Character Map read the operating system's Unicode database, not the font. What the OS does not know about will not be listed, even when the font contains the glyph.

  • Adobe: Type ▸ Glyphs with Show: Entire Font, scroll to the end. Newly added glyphs land last. That panel reads the font directly.
  • Anywhere else: paste the character, or type the shortcut (SAR, ر.س…).

I installed it and nothing changed

Almost always caching. Most effective first:

  1. Raise the version number and rebuild. Caches are keyed by PostScript name, so a version bump makes them see a different font. This is the fix that actually works; the rest is hygiene.
  2. Remove the old copy first. Same internal names means the system may resolve to the originals. macOS: Font Book → select the family → Remove. Or rebuild with a name suffix, which removes the clash entirely.
  3. Adobe cache: quit every Adobe app, find and delete AdobeFnt*.lst (several locations), relaunch.
  4. Restart the application. Apps enumerate fonts at launch. This alone fixes a surprising share of reports.
  5. macOS font cache as a last resort: sudo atsutil databases -remove, then log out and back in.

An otc file will not install on Windows

Not a fault in the file. Windows Explorer never registered the .otc extension as a font type, so it offers no Install action at all. The fix is the ttc output format — it converts CFF outlines to TrueType, and Windows has supported ttc for decades (its own system fonts ship that way).

Extra space around the symbol

Check the encoded advance before touching side bearings. A CFF glyph stores its width twice: in hmtx, and inside the charstring as an offset from nominalWidthX. Write an absolute value into the second and the glyph gains dead space — visible in Adobe apps and invisible in browsers, which read hmtx. The verification report compares the two for every glyph; an "advance mismatch" finding is exactly this.

The shortcut does not substitute

  1. Shortcuts ride on the calt feature, which can be switched off in Illustrator and InDesign (Contextual Alternates in the character panel). Check it is on.
  2. The rules are guarded deliberately: the shortcut will not fire next to a letter. SAR 10 fires, SARAH does not — by design, or every word containing SAR would break.
  3. AED500 with no space will fire, because a digit is not a letter. Intended behaviour.

The family is scattered across the font menu

A common bug in shipped fonts: the Windows nameID 2 record says Regular for every face, Bold Italic included. The build fixes it by rewriting records 1/2/16/17 from one source. If it is still scattered afterwards, the app is reading a stale cache — see above.

Arabic renders in a different font inside italics

Many families ship Arabic in the uprights only, so Arabic in an italic run falls back to a system font. Turn on "copy Arabic into the italics" in the options. The Arabic stays upright inside slanted Latin, which is the accepted convention rather than a compromise.

The symbol looks out of place in my font

The official artwork is geometric. In a naskh or heavily styled face it will look somewhat foreign, and there is no technical fix: the symbol is a state mark with one approved shape, and drawing a matching variant is a type designer's job, not a script's.
